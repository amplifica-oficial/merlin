title: Double opt-in
description: Require a confirmation click before a new signup starts receiving marketing email

---

Double opt-in adds a confirmation step between "user signs up" and "user starts getting marketing email." It's the standard way to avoid mailing typoed addresses, role accounts, and anyone who didn't actually consent.

<Callout title="No-code alternative" type="info">
  Enable **Send confirmation email (double opt-in)** on a [Form](/concepts/forms) and pick a transactional confirmation template. New contacts who submit via a landing page are created unsubscribed and Merlin sends the confirmation email immediately with `{{subscribeUrl}}`. Existing contacts keep their subscription status and do not receive another confirmation.

  For CSV imports and **Add Contact**, enable the same option and pick a transactional template. New contacts are created unsubscribed and Merlin sends the confirmation email immediately. The last template you used in those dialogs is remembered in the browser. The CSV `subscribed` column is ignored while double opt-in is enabled.
</Callout>

The trick is `{{subscribeUrl}}`: a per-contact link Merlin auto-injects into every send. Clicking it flips `subscribed` to `true` and fires a `contact.subscribed` event.

## Setup

import {Step, Steps} from 'fumadocs-ui/components/steps';

<Steps>

<Step>

### Create two templates

New projects already include a transactional **Confirm your subscription** template with `{{subscribeUrl}}`. Edit its `from` address after you verify a domain, or create your own:

- A **Transactional** template for the confirmation email, containing `{{subscribeUrl}}`:

  ```html
  <p>Hi {{firstName}}, please confirm your email to start receiving updates:</p>
  <p><a href="{{subscribeUrl}}">Confirm my email</a></p>
  ```

- A **Marketing** template for the welcome email that goes out *after* they confirm.

<Callout title="The confirmation must be transactional" type="warn">
  A marketing template targeted at an unsubscribed contact is [silently skipped](/concepts/contacts#emails-by-subscription-state). Use a transactional template for the confirmation specifically — it bypasses the subscription check.
</Callout>

</Step>

<Step>

### Trigger the signup from your backend

Two calls with your secret key (`sk_*`): create the contact unsubscribed, then track the event that fires the confirmation workflow.

```bash
curl https://next-api.merlin.example/contacts \
  -H "Authorization: Bearer sk_your_secret_key" \
  -d '{ "email": "ada@example.com", "subscribed": false, "data": { "firstName": "Ada" } }'

curl https://next-api.merlin.example/v1/track \
  -H "Authorization: Bearer sk_your_secret_key" \
  -d '{ "event": "signup.pending", "email": "ada@example.com", "subscribed": false }'
```

Both calls pass `subscribed: false`. If you skip the first call and rely on `/v1/track` alone, tracking on an unknown email creates the contact — but defaults it to subscribed, which defeats the point.

</Step>

<Step>

### Workflow A: send the confirmation

**Workflows → New workflow**:

- **Trigger**: `EVENT` on `signup.pending`
- `SEND_EMAIL` step → transactional confirmation template

Enable it.

</Step>

<Step>

### Workflow B: welcome them after confirmation

**Workflows → New workflow**:

- **Trigger**: `EVENT` on `contact.subscribed`
- `SEND_EMAIL` step → marketing welcome template

Enable it. `contact.subscribed` fires whenever a contact opts in — including via `{{subscribeUrl}}`, the preferences page, or the API — so this workflow handles both first-time confirmations and resubscribes.

</Step>

</Steps>

## CSV import and Add Contact

New projects get a transactional **Confirm your subscription** template under [Templates](/concepts/templates). Edit the `from` address after you verify a domain.

For bulk migrations or a single contact:

1. **Contacts → Import** or **Add Contact** → enable **Send confirmation email (double opt-in)** and choose a transactional template (the last one used is stored in the browser).
2. Or pass `-F "doubleOptIn=true"` and optionally `-F "confirmationTemplateId=<uuid>"` to `POST /contacts/import`. Manual create accepts the same fields on `POST /contacts`.
3. New contacts are created unsubscribed. Merlin sends the confirmation email from the selected template (`{{subscribeUrl}}` is injected automatically). Each newly imported contact also emits `contact.imported`; each newly created contact emits `contact.created`.
4. If you omit `confirmationTemplateId`, Merlin uses (or creates) the project default confirmation template.
5. Optionally add a workflow on `contact.subscribed` for a welcome email after they confirm.

Existing contacts are updated in place but keep their current subscription status — they do not receive a new confirmation email. The CSV `subscribed` column is ignored while double opt-in is enabled.

A workflow on `contact.imported` is optional. Use it only if you want extra steps (reminders, branching) beyond the confirmation email itself.

## Reminder if they don't confirm

Extend Workflow A with a `WAIT_FOR_EVENT` step after the send:

- **Event**: `contact.subscribed`
- **Timeout**: `86400` (24 hours)

On timeout, send a single reminder (also transactional). Keep the number of reminders small — repeated confirmation prompts look like spam to mailbox providers as much as to recipients.
